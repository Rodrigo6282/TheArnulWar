# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"The Arnul War" (formerly "Frente Cero", then "TheArnul's War"; localStorage keys still use the `frentecero_` prefix on purpose so saved progress survives) — an original browser FPS: Operación mode (waves of AI soldiers, 4 maps) and Zombis mode (rounds, 3 original maps: Pueblo Olvidado, Fábrica Abandonada, Base Ártica). Zombie maps declare `zombies:true` and `startZone`; `plusRing()` builds the standard 8-block ring with 4 debris gates, `ZONE_NAMES` holds the zone labels.

## Installer / distribution

`construir_instalador.ps1` builds `dist/TheArnulWar_Instalador.exe` (IExpress self-extractor, per-user install to `%LOCALAPPDATA%\Programs\TheArnulWar`, desktop + Start menu shortcuts, entry in Apps & Features) and `dist/TheArnulWar_Portable.zip`. Sources live in `instalador/` (launcher `TheArnulWar.vbs` opens Edge/Chrome with `--app` and its own profile, `instalar.bat`, `accesos.ps1`, `desinstalar.bat/.ps1`, `LEEME.txt`) plus `icono.ico`. Rebuild after every game change. `accesos.ps1` also removes the previous "TheArnul's War" install (old shortcuts, uninstall key, folders).

Fullscreen: `startPlay()` requests fullscreen (if `settings.fullscreen`) and pointer lock from the same click; Alt+Enter and the pause-menu button call `toggleFull()`. Gotchas: IExpress silently fails when SED paths contain spaces or the SED path is quoted, so the script stages in a space-free `%TEMP%` folder; keep `.bat/.vbs` CRLF + ASCII and `.ps1/.txt` UTF-8 with BOM (PowerShell 5 reads BOM-less files as ANSI). Test without installing: run the exe with `/C /T:<dir> /Q` to extract, then `instalar.bat` with `TAW_TEST=1` and `TAW_DEST=<dir>`; `cscript TheArnulWar.vbs /prueba` prints the launch command. All UI text is in Spanish; keep new UI strings in Spanish. No build step, no package manager, no tests. Git repo: https://github.com/Rodrigo6282/TheArnulWar (branch `main`; `dist*/`, `herramientas/` except `Synth_sonidos.cs` and local `backup_godot_*` are ignored).

- `index.html` — the entire game: CSS, HUD/overlay markup, and one inline `<script>` with all game code.
- `texturas/pbr1.js` — photoscanned PBR texture sets (Poly Haven, CC0: diffuse/normal/roughness, 1k) packed as base64 data URIs into `window.PBR_DATA`. They are data URIs on purpose: Chrome refuses plain image files from `file://` in WebGL (cross-origin taint), so loose .jpg files would break double-click play. Regenerate by downloading from the Poly Haven API, resizing (diff/nor 1024, rough 512) and re-packing. Materials get them via `usePBR(material,id,{color,rep,tile,ns,metal,noColor})`; `M.*` ground materials use `userData.tile` (meters per tile, applied in `makeGround`). The Play button stays disabled until `pbrPending` reaches 0. When publishing the web copy, pass this file in the Artifact `files` map at the same relative path.
- `three.min.js` — vendored Three.js **r128** (loaded locally so the game runs offline via `file://`; falls back to the cdnjs r128 URL if missing). Code uses r128 APIs (e.g. `THREE.Geometry`-free BufferGeometry, `CanvasTexture`); don't upgrade casually.

## Running / checking

- Play: open `index.html` directly in a browser (`Start-Process index.html`). No server needed.
- Node is **not** installed. For headless verification use Chrome with an isolated profile (without `--user-data-dir` it hangs on the user's running Chrome):
  ```
  "/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --user-data-dir=<scratch>/chromeprof --no-first-run --use-angle=swiftshader --enable-unsafe-swiftshader --allow-file-access-from-files --virtual-time-budget=3000 --dump-dom file:///<copy>.html
  ```
  Pattern used so far: copy `index.html` to a scratch file, point the three.js `<script>` at the absolute `file:///` path, append a script after `frame();` that stubs `initAudio`, calls `resetGame(); state='playing'; hideOverlays();`, drives the sim with `update(1/60)` and `keys.*` / `mouseDown` / `aiming`, then writes results + collected `window.onerror` messages into `document.title` and greps the dumped DOM. Use `--screenshot=<png> --window-size=1280,720` for a visual check.

## Architecture (inside the single script)

Sections are marked with `// ---------- Name ----------` comments, in this order: Settings → Renderer → Textures → World → Collision helpers → Audio → Effects → Weapons → Game state → Barrels → Enemies → Pickups → Grenades & explosions → Player actions → HUD helpers → Input → Game flow → Loop.

Key cross-cutting ideas:

- **Render pipeline** (`renderFrame()`): world (`scene`/`camera`) then, after `clearDepth()`, the first-person weapon (`holder` with `guns[]`, separate `wScene`/fixed `wCam`, so it never clips into walls) both go into `rtMain` (multisample, HalfFloat when `EXT_color_buffer_float` exists). Then bright-pass → 2× separable blur at quarter res → composite shader (`postMat`: bloom, highlight roll-off, grade, vignette tied to ADS, grain, chromatic aberration from `shake`/`hurtPulse`, desaturation at low health). Bloom only picks up HDR values >1, so "glowing" things use colors above 1 (e.g. `new THREE.Color(4,2.5,1)` for sparks, tracers, muzzle flash, red dot, lamp bulbs, sun disk in the sky shader). No three.js tone mapping/sRGB output is used; colors are authored as-is.
- **SSAO** (quality Alta only, `renderAO()`): half-res depth-only pass of the scene with `scene.overrideMaterial` (sky, sprites, motes, tracers and explosion meshes are hidden for it), AO from reconstructed view-space positions, depth-aware blur, then multiplied into `rtMain` before the weapon is drawn. Because the scene is rendered twice, `renderer.shadowMap.autoUpdate=false` and `renderFrame` sets `needsUpdate=true` right before the main pass — keep that ordering. Buildings get parapet caps and window sills/lintels in `building()`/`wallWithGaps()`.
- **Image-based lighting**: `bakeEnv()` (called from `applyEnv`) renders the sky material into a PMREM env map → `scene.environment`/`wScene.environment`, so Standard materials reflect the sky (metals, glass, water, weapon). Any shader that can be rendered into that bake must write `gl_FragColor=linearToOutputTexel(...)` — raw output into the RGBE cube target produced Inf/NaN and turned every lit surface black. Hemisphere light is scaled ×0.55 because IBL adds ambient. God rays (`raysMat` → `rtC`, per-map `env.rays`) and the lens flare (in `postMat`, occlusion via `segBlocked` toward `SUN_DIR`) are driven by `updateSunScreen()`. Wall/ground materials use their color map as `bumpMap`.
- **Medals**: `registerKill` reads `killCtx` (set in `fire()` for bullets and by `explode(...,ctx)` for `grenade/rocket/barrel/air`) to award entries from `MEDALS` via `awardMedal` (adds points, queues the animated popup drawn by `badgeSVG`). Lifetime best score + medal counts persist in `localStorage` `frentecero_profile` (shown in the menu and the game-over screen). New explosion sources should pass a ctx so kills are attributed correctly.
- **Look helpers**: `roundBoxGeo`/`rgeo(w,h,d,r)` (cached bevelled ExtrudeGeometry) for anything that shouldn't look boxy; sandbags and rubble are `InstancedMesh`es (sandbag collision/bullets go through an invisible proxy box, which raycasts still hit). `texRoads` is one 2048² canvas painted over the whole 120×120 map (roads, roundabout, markings) on a plane at y=0.01; decals use `renderOrder=2` + polygonOffset to draw above it.
- **Effects API**: `emit()` = solid chips (sparks, debris), `puff(type,pos,vel,scale)` = billboard sprites from the `PUFF` table (smoke, fire, embers, blood, muzzle smoke, flash), `impact()` picks the effect by surface (`userData.metal/wood`, material), `groundDecal()` for scorch/blood pools, `ejectCasing()`, `emitters[]` for burning wrecks. Explosion lights come from a fixed pool (`boomLights`) — never add/remove lights at runtime (forces shader recompiles).
- **Maps** (`MAPS[]` in the World section): each has `name/desc/start/yaw`, an `env` (sky colors, sun dir/color, fog, hemisphere, cloud amount, post `tint`, hill rings, weather `motes` incl. snow `fall`, enemy `uniform` colors) and a `build()` that places everything. `loadMap(i)` swaps the `world` Group, clears `colliders/worldMeshes/emitters/SPAWNS/barrelSpots/animTex`, calls `applyEnv` + `build()` + `flushInstances()` + `computeSpawns()`; always follow it with `resetGame()`. Anything a map creates must go into `world` (use `addBox/addMesh/proxyBox/instAdd`, never `scene.add`), or it will leak into other maps. Per-map RNG is `srand` (seeded in `loadMap`) so layouts are stable; big overlay canvases are cached in `this.cache`. The menu map cards (`renderMapCards`) load the map immediately as a live preview behind the menu.
- **Collision is AABB-only, not Three.js meshes.** Every solid is registered via `addBox()` → pushes a mesh to `worldMeshes` (for bullet raycasts/decals) **and** an AABB to `colliders` (for movement, LOS, grenades). Anything solid must go through `addBox`/`addCol`; removing an object (barrels) must remove it from both arrays.
  - `collideXZ(p, r, feetY, height, step)` — circle-vs-AABB push-out; boxes whose top ≤ `feetY+step` are ignored (that's how stepping/standing on crates works).
  - `groundAt()` — highest collider top under the player within reach; vertical physics snaps to it.
  - `segBlocked()` — slab test against `colliders`, used for enemy line of sight, explosion occlusion and spawn selection (cheaper than raycasting meshes).
- **Weapons** are data-driven: each `WEAPONS[]` entry has stats plus `make` (model builder returning `{model,hip,aim,flash,...}`); `guns` is built from it, keys 1–7 map to the array order. Optional fields: `falloff:[start,end,minMul]`, `scope` (sniper overlay `#scope`, hides the model, breath sway on Shift), `rocket` (projectile via `fireRocket`/`updateRockets` → `explode`), `move` (speed multiplier), `ads` (aim-in speed); model extras `bolt` (bolt-cycle anim + delayed casing) and `warhead` (hidden while empty). Recoil goes through `applyRecoil()` (smooth climb `recoilP` + springy `viewKick`), not by editing `player.pitch` directly. Airstrike is on **B**.
- **Quality setting** (`settings.quality` 0–2, `applyQuality()`): pixel ratio, shadow map size and bloom on/off. The shadow camera follows the player (`updateSun()`, texel-snapped). World materials are `MeshStandardMaterial` via `lam()`; enemies clone their materials per instance for the red hit flash (dispose on removal).
- **Player shooting** raycasts `worldMeshes` + `enemyHitMeshes()`. Enemy body-part meshes carry `userData.enemy` and `userData.mult` (head 2.3, torso 1, limbs 0.7); barrels carry `userData.barrel`.
- **Player eye / lean.** `playerEye(out)` is the single source of the head position (crouch via `eyeHeight()`, Q/E lean offset along the yaw-right vector). Camera position, enemy LOS and enemy aim all use it — keep it that way when adding stance mechanics.
- **Characters** share `buildBody()` (bone groups hips→spine→chest→neck→head, thigh→knee→foot; per-instance material clones for hit flash; `B.L` builds a limb between two points). `legPose()` drives walk/run/crouch, `deathAnim()` has 3 death variants. Soldiers carry a `B.rig` (rifle + arms) that pivots between low-ready and aiming, with `B.armL` animated for their reload; the rifle detaches (`world.attach`) on death. Every enemy type must implement `update/takeDamage/die/dispose` and expose `pos, dead, hit, revealT, mats`.
- **Navigation**: `buildNav()` rasterizes `colliders` into a 120×120 grid (call it after anything changes colliders: `resetGame`, opening zombie debris); `updateNav()` runs a BFS flow field from the player every 0.35 s; `navDir(pos,out)` gives the next step. Soldiers use it when they have no line of sight; zombies use it unless they can see the player.
- **Player reload choreography**: weapon builders return movable parts (`left` hand group, `mag`, `handle`, `slide`, `boltG`, `pump`, `shell`, `warhead`) and a `kind` (`mag|pistol|sniper|shell|rocket`). Anchors are computed once (`gd.anch`); `RTL`/`reloadPlan()` define hand keyframes + magazine windows (drop/grab/hold/insert), ammo is given at `give`. Empty vs tactical reloads differ (rack/bolt/slide release only when empty); the shotgun loads shell by shell and firing cancels it. The gun is raised/tilted during reloads so the hands stay on screen. Melee knife is `melee()` (V).
- **Zombies mode** (`mode==='zombies'`, only on maps with `zombies:true`, currently "Pueblo Olvidado"): `Zombie` class (rise → shamble/jog/run → swipe; headshots can remove the head), rounds in `updateZombies()`, spendable `points` (separate from `score`), `owned` weapons (max 2; soldiers mode owns all 7), interactables (`door` debris that opens a zone + adds its `zoneSpawns`, chalk `wall` buys, `perk` machines Blindaje/Manos rápidas/Pulso, mystery `box`) used with F via `updateInteract()/interact()`, power-ups (`maybeDropPowerUp`). Opening a door sets `zDirty`, and the next `resetGame()` reloads the map to restore it. Map layout and names are original; do not model it on any commercial game's map.
- **Enemies** (`class Enemy`): soldiers; `update(dt)` returns `false` when the corpse should be removed. AI = LOS check every ~0.2 s → engage (face, strafe, burst fire with hit-chance roll; enemies do not fire physical bullets, hits are probabilistic in `shoot()`) or chase the player; stuck detection triggers a perpendicular detour.
- **Waves** are driven by `updateWaves()` (`intermission` countdown → `toSpawn` queue, capped by alive count). Spawn points `SPAWNS` are precomputed near the perimeter, preferring ones hidden from the player.
- **Deferred actions** use the `timers` array (`{t, fn}`), processed in `updateTimers()` — used for chain explosions, airstrike, auto-reload. Use it instead of `setTimeout` for anything gameplay-related so it pauses with the game and is cleared by `resetGame()`.
- **Pools**: particles (`emit()`), tracers (`tracer()`), decals (`decal()`) are fixed-size ring buffers.
- **Audio** is fully synthesized with WebAudio (`noiseHit`, `tone`, `sfx.*`); `initAudio()` must be called from a user gesture.
- **State machine**: `state` ∈ `menu | starting | playing | paused | dead`. Entering `playing` happens only in the `pointerlockchange` handler after a successful pointer lock; losing lock while playing → `paused`. `resetGame()` must restore every piece of mutable state (add new state there).
- Map layout is deterministic: crates/barrels use a seeded RNG (`srand`), so positions are stable between sessions.

- Look / shaders: `WorldBuilder.pbr()` returns a `ShaderMaterial` on `shaders/world_pbr.gdshader` (same triplanar PBR as the old StandardMaterial3D + weather from the global shader uniforms `wetness` / `snow_cover` declared in `project.godot [shader_globals]`; uniform `vcol` multiplies MultiMesh instance colours); `pbr_std()` is the StandardMaterial3D version for code that edits material properties. Per-map film look + weather + extra exposure/ambient live in `main.LOOKS` (keyed by env id) and are applied by `apply_look()` after `apply_env()`; `post.gdshader` does split-toning, S-curve, shadow `lift` and grain. Zombie skin (`zombie._skin_look`): noise detail albedo + normal, rim, backlight; blood uses clearcoat. Known bug: `optimize.merge_world` makes some merged walls invisible (you could see through the zombie-map inner walls); ShaderMaterials are not merged, so world_pbr surfaces render correctly — fix the merge before re-enabling it for them. Dev args: `--oldmat` (old materials), `--nolook` (no grading/exposure boost), `--dry` (no wetness), `--nomergeworld`.
- Sounds: WAVs in `assets/sfx` loaded by name from `sfx.gd NAMES`. Footsteps (`step1..6`, `land`) and zombie voices (`zgroan1..5`, `zattack1..2`, `zdie1..2`) are synthesized by a C# generator (boot heel/toe + gravel grains; glottal pulses through vowel formants with creak, gurgle and saturation), source in `herramientas/Synth_sonidos.cs` (`Add-Type -TypeDefinition (Get-Content -Raw herramientas\Synth_sonidos.cs); [Synth]::Run("<ruta>\godot\assets\sfx")`, then `--import`); the old `step/zattack/zdie.wav` files are unused.
- Player state on death/respawn: input is ignored while dead (button releases too), so `player.reset_actions()` clears trigger/aim/reload/knife/grenade/climb/recoil and gun parts; it runs on death (`take_damage`) and in both `main.mp_respawn` branches — add any new per-action state there. Co-op spectating: while dead, `player._spectate()` puts the camera (`top_level`) over the shoulder of a living teammate puppet (`net_yaw/net_pitch`), left click = `spectate_next()`, HUD text via `zm.prompt = player.spectate_label()`.
- Climbing (`player._try_climb/_climb_update`, Space when facing an obstacle, or held while airborne): ledge top 0.45–2.25 m above the feet with standing room (`_fits`) → mantle; otherwise a sill with a clear opening above it and floor on the far side → vault through (camera ducks under the lintel). Position is animated directly (no collision) and fire is blocked meanwhile. In zombies mode the landing must stay ≤ 2.3 m so zone walls (3.6 m) can't be bypassed. `--climbtest` checks crate, window, tall wall and the death reset.
- Characters (Mixamo): `scripts/rig.gd` gives soldiers, multiplayer puppets, the operator preview and zombies a skinned body from `assets/mixamo/chars/*.glb` (soldiers `soldado_camo/swat/infanteria`, zombies `zombi_policia/zombi_mujer/zombi_soldado`) animated with the shared `assets/mixamo/anims.res` library (clips `idle aim walk run back left right crouch fire reload hit die_front die_back die_head`, zombies `z_idle z_walk z_run z_attack z_scream z_rise z_die z_hit`). `RIG.make(parent, id, tint)` (model turned 180° because Mixamo faces +Z), `gun_mount()` (rifle on the right-hand bone, oriented from the `aim` clip towards the left hand), `bone_node()`, and the `Aim` SkeletonModifier3D (spine pitch/yaw for aiming and hit flinches, `head_off` for decapitated zombies). Soldier/zombie AI is unchanged: `_animate_skin()` only picks clips from speed/direction/state; the procedural bodies remain as fallback (`--oldchars`). Operators pick `body` + albedo `tint` in `operators.gd`. Hit detection never used the visual body (headshot = hit height on the capsule). Source FBX files are not in the repo: to redo them copy the Mixamo downloads to `godot/assets/mixamo/raw/` (ch15/ch35/ch49/zcop/zgirl/zwar.fbx) and `anims/`, `--import`, run `herramientas/convertir_mixamo.gd` (shrinks 4K textures, writes the .glb files + anims.res), then delete raw/ and anims/. `--shot=soldiers [--near=1]` is a close-up check of the soldier bodies.
- First-person arms (`scripts/fp_arms.gd`, shader `shaders/fp_skin.gdshader`): the operator's Mixamo body stripped to arm/hand triangles (dominant bone contains Shoulder/Arm/Hand), fingers from the `aim` clip (kept playing at speed 0: a paused AnimationPlayer stops skeleton updates and the modifier never runs), a two-bone IK `SkeletonModifier3D` that puts the wrists on the gun: right hand from meta `rgrip` set by `WM.right_grip`, left hand from meta `lgrip` on the `left` node (`WM.left_guard`, custom one in `pistol()`), so reload choreography/recoil/climb move the hands. Hand orientation relative to the gun comes from the aim clip (`rel_r/rel_l`). Viewmodel cheat: `ARM_SCALE` 1.3 and `SHOULDERS` low/forward out of frame. When active the guns are built with `WM.no_hands = true`; knife/grenade keep the modelled hands. `--oldhands` restores the modelled hands. Bone poses read outside the modifier are the pre-IK ones (debug inside `_process_modification`). Shot kinds for checks: `hip_N`, `aim_N`, `reload_N` (player is god in these).
- Updates (`scripts/updater.gd`, node `Main/Updater`): at start-up asks `api.github.com/repos/Rodrigo6282/TheArnulWar/releases/latest`; if `tag_name` > `config/version` updating is mandatory: the "NUEVA VERSIÓN DISPONIBLE" window (`ui.show_update`) covers the menu with only ACTUALIZAR / Salir del juego (re-checked every 10 min when back in the menu, `updater.recheck()`): ACTUALIZAR downloads the asset whose name contains "Instalador" and ends in .exe to `user://`, runs it and quits. Release assets must keep that naming. Skipped in --autotest/--shot/--perf/--mptest; `--fakever=1.0` fakes an old version to see the window. Online handshake: the client appends `VSEP + version` to the name in `hello`; the host rejects other versions with `zzz_bad_version` (kept last in net.gd and sorted last by name so older RPC ids don't move); `--netver=X` fakes the handshake version.
- Enemies implement `take_damage(d, head) -> killed` and `dead`; kills call `game.register_kill(head, self)`. Set `game.kill_ctx` before damaging so medals know weapon/distance/melee.
- Scripts avoid `:=` on untyped values (Godot errors "Cannot infer the type"); use explicit types.
- Dev/test args (after `--`): `--autotest` (headless, all maps + both modes), `--shot=<map|zombies|rifle|smg|sniper|lmg|scope|knife|grenade|medal|reload|inspect_W_rx_ry> --map=N --q=N --out=png`, `--perf [--diag|--diag2|--diag3|--stress] --map=N`.
